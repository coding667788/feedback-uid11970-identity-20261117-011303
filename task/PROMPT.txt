请从零实现一个企业单点登录后的身份目录服务，解决多租户、多身份提供方的账号映射以及整版目录切换的一致性。上游身份验证已由本地测试适配器完成；本题只处理已验证的身份声明和账号目录，不实现令牌刷新、密码登录或外部身份平台。使用 Windows 原生 Python 3.12 标准库和 SQLite，只用 CPU，不使用 Docker、网络业务服务或现成身份管理组件。

一、身份绑定必须明确且稳定。目录按 tenant 隔离，每个账号用不可变 account_id 标识；邮箱和显示名只是可修改属性，不能用于自动匹配或合并账号。外部身份以 (tenant, issuer, subject) 三元组标识，issuer 和 subject 都按原始字符串精确匹配，不能做大小写折叠、去空白或 URL 归一化。一个账号可显式绑定多个外部身份，一个外部身份在同一版目录内只能绑定一个账号。不同租户中的同名账号、同邮箱及相同 issuer/subject 均不能串用。resolve 接口只能经预置的测试适配器凭据调用，返回 account_id、enabled 和所依据的目录 revision；未绑定或已停用的账号拒绝登录，不能因邮箱相同而接到其他账号上。

二、以整版快照更新单个租户的目录。快照包含正整数 revision、完整账号集合和完整外部身份绑定集合；未出现在新快照中的账号与绑定自发布起不可登录。绑定引用不存在账号、账号标识重复、同一外部身份重复或字段类型不符时，整版拒绝，不能留下部分修改。较高 revision 可发布；较低 revision 返回 stale；相同 revision 的等价快照为幂等成功，内容不同为 conflict。等价性忽略对象键顺序和两个集合的排列顺序，但保留字符串内容、字段类型和账号状态差异；先按明确且写入文档的 schema 校验，不得将 true 当作 revision=1、隐式转换数字字符串或吞掉未知字段。允许新快照一次性互换两条绑定的目标账号，不能因逐条更新的中间唯一性冲突拒绝一个最终合法的快照。发布结果与幂等判断必须持久化。

三、至少四个独立 HTTP 服务进程共用同一个数据库。正确性不能依赖进程内锁。并发发布不同 revision 时最终保留最高成功版本，迟到的低版本不得覆盖；并发发布相同 revision 的不同内容时只能有一个成为该版本，其他请求得到 conflict。提供批量 resolve，一次请求内的所有身份必须来自同一已发布版本；目录从“全部允许”切到“全部停用”时不能观察到一半新、一半旧。发布返回成功后新开始的查询必须使用该版或更新版。对提交前和提交后但 HTTP 响应尚未发送两处设置可控同步点，真实终止自己启动的发布进程；重启后读取目录并重试原快照，验证整版原子性、幂等性和版本不倒退，不能用抛异常代替进程终止。

交付初始化命令、HTTP 服务、目录发布和查询示例、自动化测试及 Windows 运行说明。用虚构账号和至少两个租户、两个身份提供方构造测试，重点覆盖相同邮箱不合并、三元组精确匹配、停用与移除、合法绑定互换、无效整版回滚、同版等价与冲突、不同版本竞争、批量查询与发布交错、两处进程终止恢复。并发测试用独立进程和同步点固定关键交错，参考映射及预期版本由独立逻辑产生，不能调用被测解析或查询函数计算期望值。测试日志应包含实际请求结果和最终版本，但不得输出适配器凭据；如有未完成项或失败，照实说明。
